# 一键交互迁移

在**新主控服务器**运行。迁移入口与全新部署入口分开。默认停在隔离验收，不会自动停止旧主控。

```bash
sudo -i
bash <(curl -fsSL https://raw.githubusercontent.com/Taozi-succes/marzban-panel/v1.2.1/migrate.sh)
```

如果新服务器尚未部署目标面板，会先引导配置新面板域名、订阅域名、Cloudflare 区域、证书邮箱和临时管理员等，自动准备空面板和 HTTPS。已部署的目标必须为空面板或同一面板身份的隔离验收实例；有业务用户或节点的独立目标会被拒绝覆盖。恢复旧数据后使用原管理员登录。

## 在线备份与隔离恢复

首次选择 `1`。按顺序填写：

| 提示 | 填写内容 |
| --- | --- |
| 迁移操作 | `1`：在线备份并隔离恢复；`2`：正式停机切换；`0`：退出 |
| 旧服务器 SSH 地址 | SSH 的真实 IP 或主机名，不带协议、账号或面板路径；不要填 CDN 边缘地址 |
| SSH 端口 | 实际 SSH 端口，默认 `22` |
| SSH 用户 | `root` 或有 Docker 权限的原部署账号 |
| SSH 认证方式 | `1` Agent；`2` 密钥文件；`3` 密码 |
| 私钥路径（仅方式 2） | **新服务器上的 Linux 绝对路径**，普通文件、权限 600；不能填 Windows 路径 |
| 源端 Docker 是否需要免密 sudo | root 或属于 docker 组通常填 `no`；需要 `sudo -n docker` 时填 `yes` |
| 旧主控公网 IPv4 | 原主控真实 IPv4，用于识别原主控本机出口 |
| 旧面板完整域名 | 如 `panel-old.example.com`，不带 https；使用过域名应填写，没有域名可留空 |
| 迁移备份加密口令和重复确认 | 自定至少 12 位，单独保存；脚本不保存口令 |
| 连接与执行确认 | 核对源地址、目标域名后输入 `migrate` |
| SSH 首次主机指纹 | 由 OpenSSH 提示，与旧服务器控制台指纹核对；不自动跳过校验 |
| SSH 密码／密钥口令 | 由 OpenSSH 自己隐藏提示，不写入向导状态、命令参数或日志 |
| 旧面板容器名 | 填原面板容器名；留空会列出可选面板，再输入序号 |

SSH Agent 方式可复用从本机转发到新服务器的 Agent，避免将私钥复制到新服务器。需要先通过支持 Agent 转发的 SSH 会话登录新服务器，例如 `ssh -A`；`sudo -i` 可能不保留 Agent 环境，没有 Agent 时选择其他认证方式。密码登录需要源服务器允许该账号以密码认证。向导不会更改源 SSH 权限或安装源端依赖，源端需已有 Python 3、Docker，所选账号可直接执行 Docker 或使用免密 sudo。

确认后自动完成：

1. 核对源容器身份和应用指纹，拒绝版本不兼容或把目标自身当源。
2. 通过 SSH 上传并校验通用临时工具。源端使用只读数据挂载和无网络的 Docker 辅助容器导出 SQLite 一致性快照及应用文件。
3. 通过 SSH 加密通道自动传输，在新主控生成口令加密的 `.mzb` 备份并校验全部文件和表摘要，不需要人工 SCP。
4. 调用隔离恢复，保存目标原状态，保留用户、UUID、管理员哈希、到期时间、流量、配额、线路授权、Host、节点、JWT 和管理 TLS 身份。
5. 停在隔离验收：新主控不启动核心或调度、不连接正式节点，Docker 内部网络阻止后台外联；订阅 503、修改 409。原主控继续运行。

向导不会在在线预演结束后继续停机。用原管理员登录新管理域名核对数据。在线备份之后源端新增的流量，会在正式切换时重新获取。

## 正式切换另行确认

验收完成后重新运行同一个命令，或在已更新的目标执行：

```bash
marzban-migrate
```

选择 `2`，沿用或核对 SSH 信息，填写原备份口令。向导先刷新源端报告，确认来源、应用指纹、目标完整性和主控本机出口授权。如果原主控还承担已分配给用户的本机出口，会阻止停机；需要先安排这些线路，向导不会自动搬迁原主控出口。

准备各出口云防火墙和系统防火墙，给新主控 IP 放行实际的管理和 API 端口。确认旧主控没有其他自动启动任务。在最终提示中完整输入：

```text
cutover 实际源容器名称
```

只有收到这次确认，才会停止旧主控，记录与本次源容器和目标迁移会话绑定的停机收据，重新导出最终快照、传输、隔离恢复。启动新主控前通过同一 SSH 会话再次核对旧主控仍停机、收据一致。旧主控若重新运行或被换成另一容器，流程拒绝接管。

切换完成后旧主控保持停止，不做旧域名转发。逐台确认节点、订阅、实际出口 IP 和新增计量，再通知用户使用新订阅域名。节点管理来源仍需按现有部署方式配置；公开节点安装器管理的节点可使用其 `switch-panel`，详见[手动迁移说明](migration-manual.md)。向导不替用户修改云厂商防火墙。

## 中断与文件位置

- 目标 `/opt/marzban-panel/migration/wizard.json`：进度、源连接信息、源容器身份、备份摘要和停机收据；权限 600，无 SSH 密码、备份口令或私钥内容。
- 同目录 `known_hosts`：固定源 SSH 主机身份，主机密钥变化会被拒绝。
- 同目录 `preview-*.mzb`、`final-*.mzb`：口令加密的备份，权限 600。
- 源端 `/tmp/marzban-migrate.*`：仅通用临时工具，正常结束会清理。
- 只有确认正式切换后，源端才创建 `/tmp/marzban-cutover-容器完整ID.json` 和锁文件，避免其他迁移会话误认停机状态。请保留到切换验收完成；重启或清理 `/tmp` 可能使续跑需要人工核对。

切换失败不会自动重启旧主控；它可能已经停机。重新运行选择 `2` 按同一进度继续，缺失收据、容器被替换、源重启或身份不符时会停止。目标文件恢复事务中断时，先执行 `marzban-migrate recover` 恢复目标原状态，再核对向导进度。新主控一旦已接管业务，不能直接重开旧主控回退，否则会形成双主控并丢失新数据。

当前支持同一套定制 v0.8.4、SQLite、匹配的应用指纹以及 256 MiB 内的备份。不同版本、MySQL、特殊自定义文件布局需要单独迁移。

需要逐步执行或单独备份时，原 `backup`、`freeze`、`restore`、`activate`、`verify`、`recover` 命令继续保留，见[手动操作说明](migration-manual.md)。

## 测试范围

离线测试覆盖确认边界、身份／指纹／收据校验、源重启和恢复失败。独立容器内的 OpenSSH 测试使用真实 SSH 密钥认证、主机身份校验和加密传输、真实 SQLite 备份恢复，源端 Docker 操作通过受控适配器模拟；另一个容器集成测试验证实际 Marzban 的隔离和接管运行。所有开发测试都不连接正式服务器，不修改真实 DNS、用户或节点。
